# API verification record

**Verified on 2026-10-08** against the official Notion and ClickUp developer documentation.
Every statement below was read from the vendor's own documentation (raw Markdown
pages served by `developers.notion.com` and `developer.clickup.com`) or from the
installed official SDK's type definitions. Nothing here was verified against a _live_
workspace — see [live-sandbox-testing.md](live-sandbox-testing.md) for that.

> Vendor APIs change. Re-verify before every release. Items marked **⚠ unverified**
> are things the documentation does not state and that ExitOS therefore does not rely on.

### Property types ExitOS reads

Writable in Notion: `title`, `rich_text`, `number`, `select`, `multi_select`, `status`, `date`,
`people`, `email`, `phone_number`, `url`, `checkbox`, `files`, `relation`, `place`, `unique_id`,
`verification`. Read-only/computed: `created_time`, `created_by`, `last_edited_time`,
`last_edited_by`, `formula`, `rollup`, `button`. Any type not in this list is treated as
**unsupported and reported**, never crashed on (forward compatibility).

### Block types ExitOS reads

`paragraph`, `heading_1..4`, `bulleted_list_item`, `numbered_list_item`, `to_do`, `toggle`,
`quote`, `callout`, `code`, `divider`, `table`, `table_row`, `column_list`, `column`, `image`,
`file`, `pdf`, `video`, `audio`, `embed`, `bookmark`, `link_preview`, `equation`, `child_page`,
`child_database`, `synced_block`, `link_to_page`, `breadcrumb`, `table_of_contents`, `tab`,
`meeting_notes`/`transcription`, `template` (deprecated), `unsupported`.

## Consequences for the design

1. **Notion reads use the SDK pinned to `Notion-Version: 2026-03-11`** and parse every response with Zod; both `archived` and `in_trash` are accepted.
2. **The 10,000-row cap is detected and worked around** with `created_time` windows rather than silently truncating.
3. **Plan/dry-run must allow Notion `POST` reads** (`search`, `query`) while blocking every write — so write-blocking is endpoint-classified, not just method-classified ([ADR 0006](decisions/0006-endpoint-classified-write-guard.md)).
4. **ClickUp has no create-custom-field endpoint**, so ExitOS only _populates_ existing, type-compatible fields and reports the rest.
5. **Assignees notify people**, so user mapping is explicit and defaults to _no assignment_.
6. **No idempotency keys** → provenance marker + write-ahead checkpoints + reconciliation; exactly-once is _not_ claimed.
7. **Rate limits differ by plan** (ClickUp 100/min is the usual bottleneck): the scheduler is budget-based and honours `Retry-After` / `X-RateLimit-Reset`.
8. **Docs (v3) lose several constructs** — the Markdown renderer classifies each block as supported / transformed / lossy / unsupported using this exact list.

## Not verified (and therefore not assumed)

- ClickUp's maximum task-description or Doc-page size.
- Whether `Retry-After` is ever sent by ClickUp.
- Whether `tags` on task creation auto-create missing tags (ExitOS only uses tags that already exist).
- Exact rendering of heading level 4, task lists (`- [ ]`) and `$` math in ClickUp Docs.
- Whether Custom Field values set at task-creation time count against the Free Forever "60 uses".
- Behaviour of ClickUp list endpoints immediately after a create (eventual consistency) — reconciliation therefore re-checks before retrying.
